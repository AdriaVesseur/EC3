# EC3 design system

Operational desktop software for championship drivers. Fixed navigation, one dominant preparation action, concise package rows and persistent connection state. The initial skill search suggested a landing page; that pattern was rejected. The narrower UI/UX Pro Max search returned data-dense operational dashboards, which informed the library and status displays.

Use Transducer for interface text, with Transducer Condensed for motorsport display typography and Transducer Extended for selected emphasis. The supplied JTD font files are bundled locally under the user-confirmed application license. Graphite surfaces, white type and the selected brand accent establish the visual identity; green and amber communicate named status, always accompanied by text. Use the selected MKBT or Epic logo consistently in the interface, native Windows application and favicon.

Page geometry and responsive composition remain in `src/styles.css`. The visual finish lives in `src/appearance.css`, imported last. Keep navigation, section order, columns and container widths unchanged when refining appearance.

Home's right-hand overview panel previews the first five drivers by championship position from the same source used by Championship. Display real points, the update time and a link to full standings. Loading, missing source, offline and empty results have explicit states. Championship leads with the driver classification; preparation actions stay with the content and readiness controls on Home.

Core palette: carbon `#111214`, graphite `#191b20`, raised controls `#23262d`, measured edges `#34373f`, EC3 crimson `#cf2d40`, near-white `#f2f3f6`. The same `--ec3-*` tokens drive named success, warning and error states. Light falls subtly from above: panel inset highlights, darker inner paths/search fields, precise neutral edges and restrained control shadows. Container radii are 9–12px, controls 6px and status tags 4px.

Use only bundled Transducer weights: 400 for body copy, 500 for interface labels and headings, and 700 for selective numerical emphasis. Do not use the Black face for UI titles. Every route uses the same regular-width page title, eyebrow, subtitle and season/build block. Section headings share a 20px scale; event and race names share an 18px scale, with matching smaller scales on mobile. The image banner uses Condensed Medium, as do readiness, builds and round numbers. Driver names use the regular-width family for legibility; points and times use tabular figures. Long classifications have faint alternate rows and subtle medal emphasis for the first three positions, with points aligned right. Buttons use Medium in sentence case across every page.

Components: Button, Badge/Status, Progress/DownloadProgress, ContentCard, native dialog Modal, Toast, Navigation, EmptyState, Alert, ServersPage, SponsorsFooter and AppUpdateNotice. Shared state comes from the helper; React owns only navigation, filters, open details and feedback. No installation state in browser storage.

Content reserves three equal card slots at desktop widths. Filtering to one or two cards keeps their width and aligns them left; narrower screens adapt to two or one columns. The entire photo and name area is one keyboard-accessible details button. The optional manifest `image` supplies the photo and `icon` supplies its small logo. Missing images fall back to a category illustration. Readiness figures align on a baseline with separate spacing for the current count, slash and total. Round numbers sit centered in a compact square badge. The header shows the selected launcher logo alongside navigation, with an MKBT wordmark for its compact portrait logo. Servers shares the page heading and panel tokens, displays the configured IP and HTTP port, and offers an IP copy control. Server status comes from AC `/INFO`, while live timing comes from the configured HTTPS provider. Embedded timing is opt-in and always has an external link. Sponsors form a quiet logo strip below the footer on every page. Empty configuration adds no fictitious branding.

Races adds a dedicated MKBT schedule browser using the selected launcher's accent. A compact Go Racing header and left filter rail frame large series-artwork cards, inspired by the iRacing race browser. A working Cards/Schedule switch provides a dense alternative. Search, competition, race-type and start-time/name sorting narrow the official schedule. Local favourites apply across rounds of the same series and survive reloads. The card footer keeps official entry options visible, with date, circuit, car/class and entry counts in consistent positions. Series artwork falls back to the circuit photo, then a neutral placeholder. The native detail dialog includes Overview, Participants, Standings and Results tabs, with keyboard navigation, full searchable public rosters and consistent team marks. Large full-result pages are fetched only when their selected round is opened, leaving the initial dialog fast. Full result sessions preserve every published driver and DSQ/DNF status; podium-only fallbacks are explicitly labelled. A championship roster is labelled as a series entry list rather than individual-round attendance. Data stays isolated by race and supports loading, retry, unavailable, empty and partial states. The race dialog keeps a stable viewport-bounded height, reserved scrollbar space, artwork height and tab-count slots so completed requests and failed images do not recenter or shift the interface. Registration opens the official MKBT page in the system browser; there is no simulated signed-up state. Championship entry counts are explicitly labelled as series entries. Date-only text is preserved, and timed calendar rounds use Europe/Madrid. Loading, no matches, unavailable, partial and stale schedules have explicit states. The helper reads the public calendar, championship metadata and special-event list, with a five-minute cache.

App releases have a separate version and installer from content packages. The app checks for stable published app releases, labels check failures explicitly and offers an installer download when a newer version exists. Dismissal applies to a version for the current browser session. It does not imply an automatic installation.

Keyboard focus is explicit. Native dialogs trap focus and close with Escape. Reduced-motion is respected. Mobile adapts the top navigation and stacks content row controls. Primary controls explain unavailable states. Real bytes and checked-file counts drive progress; extraction and atomic replacement use named phases without fabricated percentages.

Skills applied: `ui-ux-pro-max`, `ux-designer`, `web-interface-guidelines`, and browser test guidance from `playwright-cli`. Landing-page, hosted Sites, image-generation and Word/PDF skills were evaluated but do not fit this local installer project.

The appearance refinement also applies `frontend-design` and `redesign-existing-projects`: preserve the operational layout, use the championship's typography and selected launcher identity, and review every screen with real data as well as keyboard, contrast and responsive checks.

## Parallel launcher identities

MKBT's Standings and Results pages present the official active-season championships as cards matching Races: series cover, status, car or class, entries, rounds and next date. Completed and archived competitions never appear. Each whole card is one keyboard-accessible button opening a native, fixed-height detail dialog. Overview opens first with published metadata, description, calendar and searchable entrants; Standings and Results are adjacent tabs with arrow-key navigation. The dialog reserves artwork and scrollbar space during loading, restores focus when closed, and retains the existing team marks and classification tables. Returning to either page shows the cards; the last selected championship still feeds Home's Top 5. Cached data belongs to one championship URL; switching never exposes unrelated rows, aborts prior requests and preserves only the same competition's data on failure. Each round keeps its podium visible and loads the full Top 20 only when opened. Race 1 and Race 2 sit side by side when space permits. Table scrolling stays inside named, keyboard-focusable regions. Epic retains the single championship configured by its content manifest.

The current identity is selected at build time through `src/brand.ts`: MKBT is the default visible application, and Epic Simracing is maintained as a separate build from the same components. Launcher names, logos, favicon, app icon, native title, installer links and update notices use the selected brand. There is no public brand selector. MKBT race attribution remains visible in both builds because it identifies the official source of the calendar, registration and results.

Brand assets live under `public/brands/mkbt` and `public/brands/epic`. The logo component keeps the existing header geometry while accounting for whitespace in the supplied artwork. MKBT uses a steel-blue accent; Epic retains turquoise. Both builds retain graphite surfaces, existing typography, team-specific colours and shared loading, keyboard and reduced-motion behaviour. Published sponsor and team logos retain their own identities; a legacy sponsor identifier must not substitute the launcher's logo.

The native apps have separate installation identities, local helper ports and WebView2 profiles. Frontend cache keys use a brand prefix for championship results, race favourites and update dismissal. A cached classification, favourite or dismissed version from the other launcher must not affect the current build, even when both keys exist in a browser origin. Updates download the selected brand's installer. Browser regression coverage runs both build modes with mock helpers, checks Home, navigation, content details, identity assets, update links and storage isolation, and reserves the installed application and game data for explicit native verification.
